## Done-criterion: not met

The brief asks for at least one promotion and one rejection. **Two rejections are logged; there is no promotion.**
Every candidate improved recall on the shifted site a lot, and every one lost violation-class recall on the clean
golden set, which the gate forbids. Details and the decision this needs are at the end.

## What the loop is, and what this run is not

- Four stage modules (`ppe/monitor.py`, `ppe/diagnose.py`, `ppe/improve.py`, `ppe/verify.py`), one orchestrator
  (`ppe/loop.py`) with a state file (`runs/loop/RUN_ID/state.json`: current weights, promotion history, events, every window).
- **Monitor**: Phase 4's confidence-drift estimator (Phase 4 found it as good as all six signals), refitted on val
  cells with the scenario conditions (low light, rain) left out, so the shift is unseen. Alarm threshold = 99th
  percentile of the estimate over 200 clean-val windows, floor 0.05: **0.2234**.
- **Diagnose**: four label-free image-health checks per frame (black, flat/covered, frozen, blur) and the brief's
  three responses. 3 consecutive alarmed windows = persistent shift; shorter = temporal, wait.
- **Improve**: mine the 200 most augmentation-unstable of 400 buffered frames, pseudo-label, write a 20-frame human
  check sample, fine-tune from the current weights (10 epochs, backbone frozen) with 200 clean replay images.
- **Verify**: the brief's three rules on golden v1 (verified by sha256) and the new-site sample, mAP tolerance 0.02 fixed
  in the config before the run. Promotion keeps the last three weights; `--rollback` restores the previous one.
- **Not a real site.** Streams are 40-frame windows of TRAINING images under Phase 2 corruptions or synthetic camera
  faults. The detector has seen those images clean. The new-site sample is val under the same corruption.
- **Not a real teacher.** Pseudo-labels are the source images' own labels: a perfect-teacher stand-in, an upper bound.
  YOLO-World (`configs/loop/p5_site_shift_yolo_world.yaml`) could not run here (CLIP weights unreachable).
- **No human check yet.** Human minutes = 0. The sample is written; the human pseudo-label error rate is missing.

## Result 1: camera faults and a brief drop do not retrain (as required)

| scenario | windows | what happened | retrains |
|---|---|---|---|
| camera fault | 18 (8 faulty) | all 8 fault windows diagnosed as camera faults, human alerted: black = nonfunctional (2/2), lens covered = degradation (2/2, flagged by the blur check, not the flat-image check), frozen = stuck-at (2/2), defocus = degradation (2/2) | 0 |
| transient (rain s3, 2 windows) | 13 | both rain windows alarmed (est 0.224, 0.251; true drop 0.424, 0.425), recovered next window, logged and waited | 0 |

The frozen windows matter: their true drop is 0 (the frozen frame is a normal image) but the monitor estimate (0.265)
crossed the threshold; without the image-health check the loop would have treated a stuck camera as a site shift.

**Negative: false alarms on clean windows.** Clean training windows alarmed in 2 of 5 clean windows in every site
stream and 3 of 10 in the camera-fault stream (estimates up to 0.43 where the true drop is 0). Only the
3-consecutive-window rule kept them from triggering a retrain. The two windows that alarm (w02, w03) are the same
frames in every stream (same seed), so these are not independent counts.

## Result 2: the monitor misses a mild shift

Low light severity 2 (`p5_site_shift_mild`): over 20 shifted windows the true recall drop was 0.12 to 0.26 and the
estimate 0.07 to 0.25. Only 2 of the 20 shifted windows (w09, w13) crossed the 0.2234 threshold, never two in a row,
so the loop logged them as temporal and **never retrained** while recall stayed about 0.2 lower for the whole stream.
The estimate tracks the drop but the threshold needed to keep clean false alarms down is about the size of this drop.
This was first seen in a smoke test on the training stream, which is why the site-shift scenarios use severity 3; the
miss is kept as its own scenario.

## Result 3: site shift (low light s3) retrains; the gate rejects

Persistent shift declared at window 7 (shifted-window estimates 0.28 to 0.49, true drop 0.57 to 0.71), improve ran after window 14.
Mining picked frames with mean disagreement 0.605 vs 0.388 for the pool. Pseudo-label error vs source labels: 0 (by
construction of the stand-in teacher).

| set | metric | incumbent (best.pt) | candidate | n |
|---|---|---|---|---|
| golden v1 clean (gate) | no_helmet recall | 0.2250 | 0.2250 | 40 |
| | no_goggle recall | 0.3030 | **0.2121** | 33 |
| | no_gloves recall | 0.1897 | **0.1552** | 58 |
| | no_boots recall | 0.0000 | 0.0000 | 23 |
| | mAP@0.5 | 0.5702 | **0.5490** (drop 0.0212 > 0.02) | 141 images |
| | micro recall, all classes | 0.7154 | 0.7130 | 1,251 |
| new-site sample, val low light s3 (gate) | micro recall | 0.2287 | **0.6382** | 1,172 |
| | violation recall (pooled) | 0.0822 | 0.2055 | 146 |

**Decision: rejected** (no_goggle, no_gloves and mAP rules failed). The incumbent's golden numbers reproduce Phase 1
exactly (micro recall 0.715428, mAP 0.5702).

What this shows: the fine-tune nearly triples recall at the dark site but forgets on clean images, and the losses fall
on the violation classes (3 of 33 no_goggle, 2 of 58 no_gloves). The no_* rule compares raw recall on 23 to 58
instances, so one instance moves it by 0.02 to 0.04; the gate is strict by design and the brief sets it that way.

## Result 4: poisoned pseudo-labels; rejected, but not because of the poison

Same run with every no_* pseudo-label swapped to its compliant class: 88 of 1,547 boxes (5.7%) changed.

| set | metric | incumbent | clean-label candidate | poisoned candidate |
|---|---|---|---|---|
| golden clean (gate) | no_goggle / no_gloves recall | 0.303 / 0.190 | 0.212 / 0.155 | 0.242 / 0.190 |
| | mAP@0.5 | 0.5702 | 0.5490 | 0.5521 (drop 0.018, within tolerance) |
| new-site sample | micro recall | 0.2287 | 0.6382 | 0.6288 |
| | violation recall (pooled) | 0.0822 | 0.2055 | **0.1164** |
| golden under low light s3 | violation recall (pooled) | 0.1234 | 0.1883 | **0.1039** |

**Decision: rejected**, on one rule: golden no_goggle 8/33 vs 10/33. That is the same forgetting the clean candidate
showed, not the poison: on clean golden images the poisoned candidate is no worse than the clean one.
**The poison is visible only at the site** (violation recall 0.116 vs 0.206, and below the incumbent on golden under
low light), and **no gate rule looks at site violation recall**: rule 3 checks all-class site recall, which the poisoned
candidate still raised from 0.229 to 0.629. With a fine-tune that did not forget, this poisoned model would have passed.
This is a finding about the brief's gate, not a success of it.

## Result 5: recipe study on val only (no golden data): no recipe passes

Re-trying recipes against the golden gate would tune on the golden set, so two new recipes (written before training)
were compared with the gate rules applied to clean val instead (`ppe/recipe_study.py`). All three fail:

| recipe | val no_helmet / no_goggle / no_gloves / no_boots | val mAP@0.5 | site recall |
|---|---|---|---|
| incumbent | 22/45, 9/41, 21/56, 1/4 | 0.6389 | 0.2287 |
| r0 (the rejected candidate) | 19/45, 7/41, 18/56, 0/4 | 0.5946 | 0.6382 |
| r1: 300 replay, 5 epochs, lr 0.001 | 17/45, 2/41, 13/56, 0/4 | 0.5960 | 0.6092 |
| r2: head only (layers 0-22 frozen) | 19/45, 8/41, 20/56, 1/4 | 0.6030 | 0.6049 |

Caveat: val is the split best.pt's checkpoint was selected on, so the incumbent looks best there; this dev gate is
biased against any candidate. Even so, the direction agrees with the golden gate (r0 fails both).

## What this does and does not prove

- Proves (synthetic streams, n as stated): the loop runs end to end from one command; the diagnosis separates the four
  camera faults and a brief drop from a persistent shift; the gate rejected two candidates and logged why.
- Does not prove: anything about a real site, a real teacher, or human verification cost. It does not show the gate
  rejecting a harmful update *because* it is harmful (Result 4), and it has no promotion.

## The decision this needs

The next step changes either the training budget or the gate, and both are the project's call:

1. **Fine-tune on Colab with the full training set as replay** (all 1,132 images, unfrozen, GPU): the most likely way to
   stop the forgetting without touching the gate.
2. **Add a gate rule**: no_* recall on the new-site sample must not fall. Result 4 shows the brief's three rules cannot
   see a poison that only hurts the site.
3. **Make the no_* rule statistical** (for example, a paired bootstrap lower bound) instead of raw recall on 23 to 58
   instances. This loosens the gate and needs a sign-off.
